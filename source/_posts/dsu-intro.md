并查集，英文 Union-Find Set（虽然我没听过有人叫它 UFS，除了我自己），用来维护一堆集合，支持高效实现两种操作：

- “并”：合并两个集合；
- “查”：询问两个元素是否位于同一个集合。

并查集其实是一个森林，每一棵树都代表一个集合。而树根称之为这个集合的“代表元素”。

显然这玩意儿是很有用的（实际上也及其好写，比它好写的数据结构估计只有前缀和了），但是在讲用处之前先讲一下如何实现。

# 实现

## 朴素算法

### 存储

通常来讲表示一棵树的节点需要知道它的父节点和所有子节点，然而理论上来讲只需要父节点就可以表示了，但是这样获取子节点需要枚举所有的点，会让复杂度退化，然而并查集这一种优秀的数据结构并不需要得知子节点。

```cpp
int fa[/* Size */]; // fa[i] 代表 i 的父亲节点。特别地，如果 i 是树根，则 fa[i] = i。
```

### 查询 Find

我们知道，查询两个元素是否位于同一个集合等价于查询它们两个是否是在同一棵树种又等价于它们所在的集合的代表元素也就是树根相同。

那么一直向上跳找根就行了。

```cpp
// 不命名为 find，避免重名
// 虽然有重载，但是孩子们，这并不好玩。
// 还可以命名为 get，然而……同样会有重名问题。这并不好笑。
// 可以用 search……但是这并不直观
// *chuckle*
int findfa(int x)
{
    // 第一种写法，递归，非常直观
    return fa[x] == x ? x : findfa(fa[x]);
    // 第二种写法，迭代，效率更高
    while(fa[x] != x) x = fa[x];
    return x;
}
```

### 合并 Union

显然，只需要把一棵树的根节点连接到另一棵树上面即可。

一个显然的优化：连到另一棵树上面的最高效的做法是连到那一棵树的根节点上面。

```cpp
// union 是关键字。
// 有人用 onion。孩子们，这并不好笑。我们在讨论严肃的事情。这个东西叫做……洋葱合并法？
// 通常情况下我们命名为 merge
void merge(int x, int y)
{
    x = findfa(x); y = findfa(y);
    if(x == y) return;
    fa[x] = y;
}
```

### 时间复杂度

最坏情况下树退化成链，我们获得了开心的 $\mathcal O(n)$ 时间复杂度。

所以我们需要……

## 路径压缩 Path Compression

我们注意到我们并不关心树的形态，只关心根节点。

所以我们可以在查找的过程中，顺便把非根节点的父节点直接设成根节点。

这个技巧被称作**路径压缩**（Path Compression）。

### 存储

Unchanged.

### 查找 Find

两种写法。

```cpp
int findfa(int x)
{
    // 第一种写法
    return fa[x] == x ? x : (fa[x] = findfa(fa[x]));
    // 第二种写法
    // 这种写法正确性并不显然。但是是正确的。
    // 有论文证明了这种写法是正确的。
    while(fa[x] != x) x = fa[x] = fa[fa[x]];
    return x;
}
```

### 合并 Union

没变。

### 时间复杂度

较难分析。单次显然 $\mathcal O(n)$，但均摊复杂度 $\mathcal O(\log n)$。

这还不够快。我们需要……

## 按秩合并 Link by Rank/按大小合并 Link by Size

合并的时候，显然，我们可以把小的树往大的树上合并。

那么用一个数组表示树大小即可。只需记录根节点。

事实上，更快的做法是使用深度……也不是严格意义上的深度，它叫做秩。详见代码。

这个更快并不是指时间复杂度上的更快，而是常数上。原因详见代码。

虽然单次测速结果显示按大小合并快了 $20 \mathrm{ms}$……

### 存储

多一个 `size` 或者 `rAnk` 数组。

### 查找 Find

没变。

### 合并 Union

```cpp
void merge(int x, int y)
{
    x = findfa(x); y = findfa(y);
    if(x == y) return;
    // 第一种写法，by size
    if(size[x] < size[y])
    {
        size[y] += size[x];
        fa[x] = y;
    }
    else
    {
        size[x] += size[y];
        fa[y] = x;
    }
    // 第二种写法，by rank
    // rank 会重名。这并不好笑。
    if(rAnk[x] < rAnk[y]) fa[x] = y;
    if(rAnk[y] < rAnk[x]) fa[y] = x;
    if(rAnk[x] == rAnk[y])
    {
        // 显然，自增比加法要快。
        // 这就是为什么 by rank 更快。
        rAnk[y]++;
        fa[x] = y;
    }
}
```

### 时间复杂度

单独使用路径压缩或者按秩合并都是 $\mathcal O(n \log n)$ 的。

都使用非常难以分析，但是紧的上界是 $\mathcal O(n \alpha (n))$，其中 $\alpha(n)$ 是阿克曼函数的反函数，增长极其慢。慢道什么程度呢？对于所有能够直接想象的数字（如可观测宇宙中所有原子的数量 $10^{308}$，物理上来讲任何超过这个值很多的数字都是没有意义的），$\alpha(n)$ 都是 $\le 4$ 的。通常来讲，我们在计算的时候把它看做 $\mathcal O(n)$ 较为方便，但是严格来讲，它是超线性的。

至于为什么，读者自证不难……好吧其实很难。详见算法导论（并查集在算导里面叫做“用于不相交集合的数据结构”的“不想交集合森林”）或者其它资料。

# 用途

## 基本用途

看啥看，先 A 掉 P3367【模板】并查集再说。

另外，如果题目本身就是维护一个森林，支持把一个节点变为领一个节点的子节点，或者查询树根……那么就变成真正的裸题了。然而如果要支持断开，则不能路径压缩，但是仍然可以按秩合并。应该有这样的题，忘了是哪道了。

另外还可以用于一个图中不停加边、找环、找两点之间是否有路径、求图中连通块数量等等。不能删边。

例题：P1111（加边、求连通块数量），P1396（排序、加边、判断是否连通），P1536（加边、求连通块数量、少许关于树的知识）。

不能删边，这可怎么办呢？如果全是删边操作，那么我们可以把操作离线下来，“时光倒流”，反着顺序加边。如 P8059。

Kruskal 最小生成树算法的高效算法也用到了并查集，然而并查集的时间复杂度（带 $\alpha(n)$）并不是瓶颈，瓶颈在于排序，如 P3366，P1195。

## 种类并查集

问题：有 $n$ 个布尔变量 $a_{1 \dots n}$，$m$ 个条件，每个条件都形如 $a_i=a_j$ 或 $a_i\not =a_j$，保证不会无解（或需要判断是否无解），每次询问求 $a_i$ 和 $a_j$ 的关系（相等、不等、或者未知）。

或者，条件和询问交替，或许这样条件应该叫做操作更合适一点……

我们的思路就是，把所有相同的数字放在一个集合中，然而这里不同和未知就无法区分了。

我们需要一点奇妙的思路。

我们对于每个 $a_i$，不仅对 $a_i$ 建一个节点，还对 $1 - a_i$ 建一个节点。

这样等于关系和不等关系就完美解决了。

几乎是模板题：P1525。
