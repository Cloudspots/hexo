原来这题可以写题解吗。

首先注意到这样的图形很美妙，比如这样是合法的：

```plaintext
  X
 XXX
 XXXXX
XXXXXX
 XXXXXXX
    XXXX
       XX
```

但这样不是：

```plaintext
XXX
 XXX
  XXX
  .XXX
  XXXXX
   XXX
    X
```

注意这个 `.`，它不满足条件。

我们考虑量化一下条件。容易发现，图形合法等价于每一行和每一列的黑色（有草）格子都是连续段。

稍微感知一下就会发现：

- 每一列的黑色格子都是连续段。
- 每一列的上端点（整个图形的上边界）是单峰的，下端点（整个图形的下边界）是单谷的。

我们考虑这个峰和谷的位置。我们还没有说明什么叫做峰，什么叫做谷。直觉上，峰就应该是上升到下降到分界点，谷就应该是下降到上升到分界点。这样定义有一些小问题，但是不影响大的思路，我们待会儿再考虑。

那么在一个图形中，每一列有五种情况：

0. 这一列没有黑色格子。它在左端点左边或者右端点右边。
1. 这一列有黑色格子，它在峰和谷的左边。
2. 这一列有黑色格子，它在峰的右边，谷的左边。
3. 这一列有黑色格子，它在峰的左边，谷的右边。
4. 这一列有黑色格子，它在峰和谷的右边。

现在我们有必要来讨论一下细节了。

- 峰的精确定义是，设第一个开始下降的位置为 $x,x+1$，则峰为 $x$。
- 谷的精确定义是，设第一个开始上升的位置为 $x,x+1$，则谷为 $x$。
- 对于上面的五种情况的后四种，如果恰好在峰上/谷上，我们定义它在峰/谷的左边。即，这里的左边是“不在右边”的意思，而右边是严格的。

现在我们一列一列考虑，有很明确的状态标识：纵坐标 $y$，下边界 $l$，上边界 $r$，和此时的状态 $1,2,3,4$。这里没有状态 $0$，原因很显然，引入不会有好处。

我们考虑如何转移。设上一列的两个端点分别为 $l',r'$，这一列为 $l,r$。

- 状态 $1$ 可以凭空产生，也可以从上一列的状态 $1$ 转移而来。能够转移当且仅当 $l\le l'\land r\ge r'$。
- 状态 $2$ 不可以凭空产生，但是可以从状态 $1$ 转移而来，也可以从状态 $2$ 转移而来。从状态 $2$ 转移而来当且仅当 $l\le l'$ 且 $r\le r'$，从 $1$ 转移而来条件相似但是不可以 $l=l'$。
- 状态 $3$ 类似，只能从 $1$ 或 $3$ 转移而来。从 $3$ 转移而来的条件是 $l\ge l'$ 且 $r\ge r'$，从 $1$ 转移而来需要 $l\ge l'$ 且 $r>r'$。
- 状态 $4$ 可以从状态 $1,2,3,4$ 转移而来，是最复杂的转移（大概估了一下，我代码中这一行的长度是上面几行的 $2\sim 3$ 倍）。从状态 $4$ 转移而来当且仅当 $l\ge l'$ 且 $r\le r'$，从 $3$ 转移而来还需要 $r\neq r'$，从 $2$ 转移而来还需要 $l\neq l'$，从 $1$ 转移而来需要上面所有条件（即，$l>l'$ 且 $r<r'$）。

对于每个状态对答案的贡献，可以立即在这里结束，所以直接加上这个状态的值即可。

直接做很慢，但是有显然的二维前缀和优化，所以转移可以做到 $O(1)$，总时间复杂度就是 $O(n^3)$，虽然但是常数很大就对了。

注意到有一些状态是不合法的，即里面有没有草的格子。这个你每一列分别前缀和即可。

小练习：如果我改成 $n$ 行 $m$ 列，保证 $nm\le 5\times 10^4$，如何做？直接做是 $O(mn^2)$ 的，可以让 $n$ 很大，然后你就炸了。

延伸阅读：[CF273D 题解](https://www.luogu.com.cn/article/rj3skbam)。

```cpp
#include <cstdio>
#include <string>
#include <iostream>
#include <algorithm>

using namespace std;

long long dp[155][155][155][4];
long long vdp[155][155][155][4];
int mp[155][155];
int vsum[155][155];

int main()
{
	int n;
	scanf("%d", &n);
	for(int i=1;i<=n;i++)
	{
		while(getchar() != '\n');
		for(int j=1;j<=n;j++)
		{
			mp[i][j] = getchar() == 'G';
			vsum[i][j] = vsum[i-1][j] + mp[i][j];
		}
	}
	auto qsum = [](int y, int xl, int yl, int xr, int yr, int op) -> long long { return (vdp[y][xr][yr][op] - vdp[y][xl-1][yr][op] - vdp[y][xr][yl-1][op] + vdp[y][xl-1][yl-1][op] + 2 * 1000000007) % 1000000007; };
	long long sum = 0;
	for(int y=1;y<=n;y++)
	{
		for(int l=1;l<=n;l++)
		{
			for(int r=l;r<=n;r++)
			{
				if(vsum[r][y] - vsum[l-1][y] == r - l + 1)
				{
					dp[y][l][r][0] = (qsum(y-1, l, 1, r, r, 0) + 1 + 2 * 1000000007) % 1000000007;
					dp[y][l][r][1] = (qsum(y-1, l, r, r, n, 1) + qsum(y-1, l, r, r, n, 0) - qsum(y-1, l, r, r, r, 0) + 1000000007) % 1000000007;
					dp[y][l][r][2] = (qsum(y-1, 1, l, l, r, 2) + qsum(y-1, 1, l, l, r, 0) - qsum(y-1, l, l, l, r, 0) + 1000000007) % 1000000007;
					dp[y][l][r][3] = (qsum(y-1, 1, r, l, n, 3) + qsum(y-1, 1, r, l, n, 1) - qsum(y-1, l, r, l, n, 1) + qsum(y-1, 1, r, l, n, 2) - qsum(y-1, 1, r, l, r, 2) + qsum(y-1, 1, r, l, n, 0) - qsum(y-1, l, r, l, n, 0) - qsum(y-1, 1, r, l, r, 0) + dp[y-1][l][r][0] + 4ll * 1000000007) % 1000000007;
					sum = (sum + dp[y][l][r][0] + dp[y][l][r][1] + dp[y][l][r][2] + dp[y][l][r][3]) % 1000000007;
					// printf("dp[%d][%d][%d] = {0: %lld, 1: %lld, 2: %lld, 3: %lld}\n", y, l, r, dp[y][l][r][0], dp[y][l][r][1], dp[y][l][r][2], dp[y][l][r][3]);
				}
			}
		}
		for(int l=1;l<=n;l++)
		{
			for(int r=1;r<=n;r++)
			{				
				vdp[y][l][r][0] = (vdp[y][l][r-1][0] + vdp[y][l-1][r][0] - vdp[y][l-1][r-1][0] + dp[y][l][r][0] + 1000000007) % 1000000007;
				vdp[y][l][r][1] = (vdp[y][l][r-1][1] + vdp[y][l-1][r][1] - vdp[y][l-1][r-1][1] + dp[y][l][r][1] + 1000000007) % 1000000007;
				vdp[y][l][r][2] = (vdp[y][l][r-1][2] + vdp[y][l-1][r][2] - vdp[y][l-1][r-1][2] + dp[y][l][r][2] + 1000000007) % 1000000007;
				vdp[y][l][r][3] = (vdp[y][l][r-1][3] + vdp[y][l-1][r][3] - vdp[y][l-1][r-1][3] + dp[y][l][r][3] + 1000000007) % 1000000007;
			}
		}
	}
	printf("%lld\n", sum);
	return 0;
}
```
