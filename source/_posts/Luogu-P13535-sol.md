## $N=3$

$N=2$ 过于显然，不讨论。而考虑完 $N=2$ 明显应该来看这个，而不是其它奇怪的部分分。

首先第一次我们只能花 $P_0-1$ 或 $P_0-2$，否则可以构造 $P_1=P_0-1,P_2=P_0-2$ 使得买任何 $< P_0-2$ 的钱都买不到任何东西，不合法。

而 $P_0-2$ 看着就很不优。考虑 $P_0-1$。

另外，“剩余钱数”不是很有用，有用的是它与 $M$ 的差，即“本次购买的所有纪念品的总钱数”。

分类讨论。

- $P_0-1$ 买到了一个纪念品：显然买到的是 $P_1$。那么，我们就能知道 $P_1$ 的价格。然后我们买两次 $P_1-1$ 就相当于两次 $P_2$ 了。
- $P_0-1$ 买到了两个纪念品：我们需要构造一个数字 $x$，满足 $P_2\le x<P_1$，这样才能刚好买到 $P_2$。我们现在知道了 $P_1+P_2$，容易发现（并不需要很强的直觉和注意力），$x$ 取 $\dfrac{P_1+P_2}{2}$（即它们的平均值）即可。因为是整数，而又可以和 $P_2$ 取等，所以向下取整即可。

**启示**：平均。将其推广，对于任意 $k$ 个纪念品，将其平均都能得到一个介于 $\min$ 和 $\max$ 之间的价格。既能保证不选中 $\max$，又能保证成功选中某个纪念品。

## $P_i\le P_{i+1}+2$

由于 $P_i=N-i$ 过于简单且是这个的子集，所以直接考虑这个。

我们依旧考虑第一次购买 $P_0-1$。实际上在最后的正解中，我们也是这么做的，这个应该都能猜到。

我们可以猜测，要么买到 $P_1$ 剩余 $1$ 元（以下用“元”代表“硬币”），要么买到 $P_1$ 并不剩。实际上这个不完全对……如果某个 $P$（如果可能，显然必然是 $P_{n-1}$）为 $1$，那么也可能是买到 $P_1$ 和 $P_{n-1}$，不剩。但是这种和剩余 $1$ 元近乎等价，还可以顺便知道 $P_{n-1}$。

这样我们就可以推出 $P_1$ 的价格，最多额外购买一次 $P_{n-1}$。接着推出 $P_2$，接着 $P_3$……这样就可以推出所有的价格了，而 $P_{n-1}$ 始终不可能超限。然后把所有纪念品次数补满即可。

**启示**：可以先推出所有价格，保证推出的过程中次数不超限，最后补满剩余次数。

## 正解

我不知道 Subtask 5 怎么用……直接考虑正解。

首先第一步肯定是买 $P_0-1$，这个没得说。

第二步我们好像迷失了方向，但是别忘了我们有一招：取平均。

这时候有一个边界条件。如果 $P_0-1$ 只买到一个纪念品，则取平均还是这个纪念品。但既然只有一个，显然是只买到 $P_1$，我们还就能知道 $P_1$ 的价格了。然后购买 $P_1-1$，我们发现这时候的情况和原本完全一致！所以不管即可。

显然直接购买 $P_0-1$ 会买到 $P_1$（可能还会有其它东西），所以取平均数后就必然不会买到 $P_1$！假设取平均后买到的第一个纪念品（价格最大的，编号最小的）为 $P_k$，则我们按照上面的方法递归进行下去，最终必然会落到某个上面的边界条件上。我们就成功获取了一个 $P$（不一定是 $P_k$）的价格！

但是我们知道一个的价格之后就只能停下了吗？不！“边界条件”中我们还讨论了，可以继续下去！以此类推我们就得到了一系列 $P$ 的值，并且必然包括 $P_{n-1}$。

知道了这些有什么用呢？

上面的算法已经有递归的影子了。我们考虑分治。假设我们取平均得到了 $P_{k+1},P_{k+2},\dots,P_{n-1}$ 的价格，那么我们再来看看第一次取的 $P_0-1$：其 $\min$ 必然小于 $P_k$，所以其中一些纪念品的价格我们是知道的！而把这些东西去掉，再次取平均，就得到了一个另一个值，它要么等于 $P_1$，要么介于 $P_1$ 和 $P_k$ 之间。我们这样递归下去即可（如果等于 $P_1$，则按照边界条件的方法递归下去）。

但是，递归下去会有影响，它可能不小心买到 $P_k$ 之外的元素。实际上这无伤大雅，用数学归纳法容易证明最终总次数还是不超过上界的。

这样我们的分治算法就最终出来了。时间复杂度？虽然这道题复杂度不重要，看看数据范围 $100$ 就知道了。但还是可以分析一下。我们假设交互库每次 `transaction` 的复杂度为 $O(n)$（可以优化到 $O(k\log n)$，$k$ 是实际选中的纪念品数量，但是我们不管），那么我们的分治算法的时间复杂度是 $T(n)=\max\limits_k(T(k)+T(n-k))+O(n)$。划分可能不均匀。显然当 $k$ 取 $1$（或 $n-1$）时最劣，是 $T(n)=T(n-1)+O(n)=O(n^2)$。

然而别忘了最后还需要将没有满次数的补满。这时候如果交互库用上上面说的优化，就能够实现 $O(n^2\log n)$（上面的分治也会多一个 $\log$，但是无伤大雅）。否则是 $O(n^3)$。可以构造 $P_i=K-i$，其中 $K$ 是一个很大的数字来达到这个上界。

总而言之复杂度是 $O(n^3)$ 或 $O(n^2\log n)$，可过。主要复杂度是交互库带来的。

upd：原来还有交互次数上界。这个更加简单。感性理解一下，每次至少买到一个纪念品，而可以构造数据使得即使是最优解每次都之多买到一个纪念品。所以如果上面的方案不行，那么整个题都是不可做的。或和理性分析一下，交互次数最多是 $\displaystyle\sum_{i=0}^{N-1} i=\dfrac{N(N-1)}{2}=4950$。

#include "souvenirs.h"
#include <utility>
#include <vector>
#include <cstdio>
#include <map>

using namespace std;

auto U = [](auto x) { return [x](auto ...y) { return x(x, y...); }; };

long long sp[105];
int cnt[105];

pair<vector<int>, long long> ps(const pair<vector<int>, long long> &x)
{
	vector<int> ra;
	long long b = x.second;
	for(int v : x.first)
	{
		if(sp[v]) b -= sp[v];
		else ra.push_back(v);
	}
	return {ra, b};
}

map<long long, pair<vector<int>, long long>> mp; // 为了方便。在第 56 行我们获取了一次，然而第 57 行进入递归时还会再获取一次，此时会发生重复，可能会超限。所以加上记忆化。

pair<vector<int>, long long> gt(long long x)
{
	if(mp.count(x))
	{
		mp[x] = ps(mp[x]);
		return mp[x];
	}
	// printf("get(%lld)\n", x);
	auto [a, b] = transaction(x);
	for(int y : a) cnt[y]++;
	return mp[x] = ps({a, x - b});
}

void buy_souvenirs(int n, long long mx)
{
	sp[0] = mx;
	U([&](auto &&self, int l, int r, long long val) -> void
	{
		if(l > r) return;
		auto res = gt(val);
		if(res.first.size() == 1)
		{
			sp[res.first[0]] = res.second;
			self(self, res.first[0] + 1, r, res.second - 1);
			self(self, l, res.first[0] - 1, val);
		}
		else
		{
			auto v = gt(res.second / res.first.size());
			self(self, v.first[0], r, res.second / res.first.size());
			self(self, l, v.first[0] - 1, val);
		}
	})(1, n-1, mx - 1);
	for(int i=0;i<n;i++)
	{
		while(cnt[i]++ != i)
		{
			// printf("get(%lld)\n", sp[i]);
			transaction(sp[i]);
		}
	}
}
